# حسابات استطلاع يدوية — تطوير/اختبار فقط

هذا وضع جديد في **نفس CLI للـseed الموجود**. لا تشغيل تلقائي عند dev/start/build أو النشر، ولا API لإنشاء هذه الحسابات. لا OTP أو Whapi، ولا تغيير لمنطق تسجيل/تفعيل المستخدمين.

## التشغيل

من Shell في هذا المشروع:

```sh
NODE_ENV=development npm run db:seed -- --manual-scenarios --confirm-development
```

يبقى `npm run db:seed` بلا flags هو seed المراجع فقط؛ لا ينشئ حسابات اختبار.
يفشل الوضع اليدوي إذا كانت المراجع المطلوبة مفقودة/غير نشطة. لا ينشئ أو يعدّل المراجع تلقائيًا.

## بيانات الدخول الوهمية

كلمة المرور المشتركة: `TEST_ONLY_Syriacar_2026!`

## الاستطلاع

- الحسابات 1–4: الحساب ← الفحص الفني.
- no_match: اختر **دمشق / مدينة دمشق** للحساب الرابع. يتحقق seed من عدم وجود مزود نشط قادر على الأبعاد الخمسة في هذه المحلية، حتى لو كان مغلقًا وقت تشغيل seed؛ إذا وُجد يوقف المعاملة، ولا يعدّل أي مزود.
- لا ينشئ هذا seed مزودي خدمات. verified/pending يختبران صلاحية اختيار المركبة؛ لا ضمان لنتيجة matched دون مزودي فحص مناسبين حقيقيًا في بيانات التطوير. rejected غير قابل للاختيار، مع رابط التعديل القائم.
- الحساب الخامس: الحساب ← خدمة السطحة؛ الانطلاق يبدأ دمشق، ويمكن تعديله دون تغيير ملف السكن.
- الحساب السادس: الفحص يعرض حالة عدم وجود مركبة ورابط إضافة مركبة.

للتحقق اختياريًا في Chromium بعد إنشاء البيانات:

```sh
node --conditions=react-server tests/manual-seed-browser.mjs
```

يفحص تسجيل الدخول الحقيقي والحالات الستة عبر Next دون mock للـAPI. لا يؤكد طلب خدمة؛ يمنع كل الكتابات عدا login للحسابات التجريبية. نشاط هذه الحسابات وتجديد جلستها يتبعان النظام العادي.

## السلامة وإعادة التشغيل

- Stable UUIDs بأسماء مستقلة عن بيانات البشر، وعملية واحدة ذرية مع قفل لمنع تكرار التشغيل المتزامن.
- Insert-only؛ يعيد التشغيل دون نسخ إضافية ودون إعادة ضبط كلمات المرور أو الحالات أو home governorate أو last_active_at. التعديلات اليدوية على المركبات تبقى كما هي.
- تصادم رقم الهاتف مع مستخدم آخر، أو ID غير موثوق، أو حساب تجريبي معطل/محذوف/كلمة مرور معدّلة يوقف seed كاملًا؛ لا upsert أو overwrite للمستخدمين الموجودين.
- لا request أو notification أو OTP challenge أو provider أو Operations account أو بيانات مرجعية جديدة.
- يمنع `NODE_ENV=production` والبيئات غير المعروفة وpublished runtime (`REPLIT_DEPLOYMENT`) حتى مع NODE_ENV مُغيّر. توجد بصمة غير سرية مثبتة لعنوان/اسم قاعدة **التطوير الحالية**؛ target آخر مرفوض قبل الاتصال.
- لا يُستخدم override للبصمة. بعد نقل المشروع إلى قاعدة تطوير/اختبار مختلفة، يجب التأكد من هوية قاعدة التطوير المستقلة أولًا ومراجعة allowlist في المصدر؛ لا تضع عنوان قاعدة Production أو أسرارًا في المصدر.
- لا تُنسخ حسابات التطوير هذه تلقائيًا من خلال seed. **عند النشر لا تختَر نسخ بيانات قاعدة التطوير إلى Production**؛ تلك عملية منفصلة من منصة النشر وقد تنسخ البيانات الوهمية. حماية CLI لا تستطيع منع نسخ يدوي خارج CLI.

## نتائج التحقق عند التسليم

- `npm test`: نجحت 133/133، بما فيها 12 اختبارًا جديدًا للـseed. اختبارات البيانات في schema مؤقت داخل rollback-only transaction، لا في بيانات التطبيق الحقيقية.
- `npm run typecheck` و`npm run build`: ناجحان.
- `npm run db:verify-isolated`: نجحت 243 assertion والمراجع الـ158؛ schema الحقيقي لم يتغيّر.
- جرى تشغيل CLI الفعلي مرتين في التطوير: الأولى 6 حسابات و4 مركبات؛ الثانية صفر سجلات جديدة. مقارنة جميع السجلات السابقة عبر الجداول الـ24 أثبتت بقاءها دون تغيير، ولم تُضف سجلات في أي جدول آخر.
- `tests/manual-seed-browser.mjs`: نجحت الحالات الستة بتسجيل الدخول الفعلي وAPI الفعلي، دون إرسال OTP/Whapi أو إنشاء requests/notifications.
