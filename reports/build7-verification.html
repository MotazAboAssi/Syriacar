تقرير تسليم Build 7 — خدمات الفحص والسطحة للمسجّل

التاريخ: 4 أكتوبر 2026. التنفيذ وفق الخطة المعتمدة، SRS v1.4 وDBMS v2.2 وUI/UX v1.3.

النتيجة: اكتمل نطاق Build 7 ونجحت اختبارات المسجّل والـregression للضيف والحساب. لا عائق جديد يستلزم STOP/report. لم يبدأ تنفيذ مرحلة لاحقة.

ما تم تنفيذه

  • الفحص: اختيار مركبة مملوكة وغير rejected ومحلية نشطة إلزامية؛ حالة المركبات الفارغة ترتبط بإضافة مركبة U-07، والمرفوضة غير قابلة للاختيار مع رابط التعديل الحالي.
  • المطابقة AND للأبعاد الخمسة بالـIDs، وyear_category من قاعدة البيانات، مع active/open بتوقيت دمشق والمحلية. التخصصات عرض فقط، ولا wildcard للقدرات المفقودة.
  • عرض OSM/Leaflet مع markers للزوج الصالح فقط، وقائمة للمزود بلا إحداثيات أو بإحداثيات غير صالحة. الإحداثيات لا تؤثر على suitability. fallback عند فشل tiles أو تجاوز خمس ثوانٍ، دون تغيير المحلية أو المطابقة.
  • المناسب فقط يقبل إشعارًا. no_match يتطلب تأكيدًا صريحًا وينشئ parent بلا notification؛ يظهر contact_phone المضبوط فقط بلا رقم بديل.
  • السطحة: محافظة السكن النشطة prefill للانطلاق مع إمكان التعديل، والمحافظة غير النشطة تتركه غير محدد دون تعديل الملف. destination إلزامي، ولا اختيار مركبة.
  • Section A/B وترتيب origin ثم destination ثم RANDOM من المنطق القائم. التأكيدات المتتابعة تستخدم parent واحدًا؛ B→A→B يرقّي إلى matched دون downgrade.
  • الموقع: GPS للعرض في الفحص؛ وفي السطحة يُجهّز رابط Google Maps في ذاكرة المتصفح فقط. fallback محافظة/منطقة يدوي يتحقق من ملكية parent وnotification ولا يغيّر مسار الطلب.
  • التواصل: روابط wa.me من whatsapp_number، لا phone، وبالقوالب FR-INS-013 وFR-TOW-009 والموقع. المستخدم يرسل الرسالة بنفسه؛ لا WhatsApp API لإشعارات المزود.
  • الحماية: جلسة JWT الحالية، فحص المستخدم الموجود/النشط/غير المحذوف، ملكية المركبة والـparent والـnotification، تثبيت سياق continuation، Origin للكتابة، body محدود، وإعادة تحقق الحالة داخل transaction.
  • الواجهة: RTL، عرض 320px، bottom/side sheets، focus ولوحة مفاتيح، targets ≥44px، منع الضغط المكرر أثناء التأكيد، إبطال النتائج والردود القديمة، وإعادة التوجيه إلى تسجيل الدخول عند انتهاء الجلسة.

التغطية الأساسية الجديدة

  • القدرات الخمس مستقلّة، pending/verified مقابل rejected، year_category من DB، إحداثيات سليمة/null/غير صالحة، وحدود ساعات دمشق.
  • User A/B، مركبة مستخدم آخر، parent ضيف أو خدمة أخرى، تغيير المركبة/المحلية/المسار، notification لا يتبع parent، جلسات missing/tampered/expired/disabled/deleted وغير موجودة.
  • رفض client identity/capabilities/matching/GPS والحقول غير المعتمدة، الحماية عبر Next الفعلي وOrigin العام، cache-control=no-store.
  • إنشاء السجلات بالحقول registered الصحيحة وguest fields=NULL؛ rollback عند فشل notification، بما فيه تراجع promotion للـparent السابق؛ تاريخ matched يبقى محفوظًا.
  • الخريطة المختلطة، مزود مناسب بلا marker، فشل/timeout، no_match/cancel/refresh، stale responses، busy، home active/absent/inactive، same-governorate، B→A→B، قوالب WhatsApp، GPS success/denial وmanual fallback.
  • الـsheets وRTL و320px وحجم controls، فتح marker بلوحة المفاتيح، وعدم overflow أفقي.

حدود التحقق والمحافظة على النطاق

  • لا schema change ولا migration مطبّقة على schema الحقيقي. فحص DB استخدم rollback-only isolation.
  • Guest contracts وflows وملفات اختبارات baseline لم تُعدّل. أُعيد استخدام المراجع العامة والمنطق القائم بالقراءة/import فقط.
  • لا OTP/Whapi حي في الاختبارات، ولا إرسال رسائل فعلي. الحسابات والمركبات test-only داخل معاملات PostgreSQL المتراجعة؛ لا credentials حقيقية في harness.
  • اختبارات المتصفح تعرض التطبيق الفعلي وتستدعي handlers الحقيقية ضمن PG rollback-only عبر interception يمنع كل fallback إلى API حي. tiles وحالات geolocation محاكاة للتحقق المتكرر؛ لا ادعاء بالتحقق من توفر OSM الخارجي في جميع الشبكات أو GPS جهاز حقيقي.
  • lookup/location والقراءة لا تنشئ أو تعدّل requests/notifications؛ تحديث نشاط المستخدم وتجديد cookie يتبع جلسة Build 6 الحالية.
  • لم تُغيّر إعدادات النشر أو OTP/Whapi callback؛ لم يبدأ Build لاحق، ولم تُضف booking أو ranking أو geocoding أو Google API أو GPS storage/logging.
